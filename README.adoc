This project contains the Android Apps based on the Cyface SDK.

This app uses

* the Cyface SDK to capture sensor and location data on Android devices
* the Cyface Energy Settings to check phone settings required for location capturing in background
* the Cyface Camera Service to capture visual footage

These three projects are included as Git submodules and are developed in their own repository.

[[installation-guide]]
== Installation Guide

To download the Cyface libraries (SDK, Energy Settings, Camera Service):

[arabic]
* You need a Github account with read-access to these Github repositories
* Create a https://github.com/settings/tokens[personal access token on Github] with `read:packages` and `repo` permissions to download the sub-modules and `android-publish` dependency.
* Copy `gradle.properties.template` to `gradle.properties` and adjust:
+
....
githubUser=YOUR_USERNAME
githubToken=YOUR_ACCESS_TOKEN
....
* Build the app `./gradlew build`

[[inject-secrets]]
=== Inject Secrets

The App uses a few APIs which require authentication.
The credentials are usually injected by the CI:

==== Sentry

Create a file `sentry.properties` at the root of a UI project with the following credentials,
the `auth.token` can be found on `Sentry > Settings > Account > API > Auth Tokens` of the EU
organization `cyface-eu`.

....
defaults.project=android-app
defaults.org=cyface-eu
auth.token=SECRET_TOKEN
....

==== Google Maps

Add the following to your `gradle.properties` file:
....
google.maps_api_key=SECRET_KEY
google.maps_api_key.r4r=SECRET_KEY
....

==== Authentication and Data Collection APIs

Add the following to your `gradle.properties` file (the release build uses them):

....
cyface.api=https://some.url.com/api/v4
cyface.provider_api=https://some.url.com/provider
cyface.incentives_api=https://some.url.com/incentives
cyface.oauth_discovery=https://some.url.com/auth
cyface.oauth_redirect=de.cyface.app:/oauth2redirect
cyface.oauth_redirect.r4r=de.cyface.app.r4r:/oauth2redirect
digural.api=https://some.digural.url.com
....

The other build types read the same properties with a prefix: `cyface.staging_*` (also `cyface.staging_user` and `cyface.staging_password`), `cyface.demo_*`, `cyface.emulator_*`, `cyface.local_*` and `digural.staging_api`. See the `buildConfigField` lines in `ui/*/build.gradle`. The CI uses the mock API `https://demo.cyface.de`, which accepts all credentials, so that the UI tests can skip the login.

[[importing-the-cyface-depeendencies-as-submodules]]
=== Importing the Cyface Dependencies as Submodules

These libraries are downloaded as packages, see the installation guide at the top of this Readme.
If you want to include the Cyface libraries as submodules for easier development:

To get the current submodules' code run the following command:

....
$ git submodule update --init
....

If the referenced SDK version changed you can get the new code by executing:

....
$ git pull
$ git submodule update
....

If you want to select a specific submodule version you can do this by using the normal Git commands:

....
$ cd submodule/
$ git fetch -p
$ git checkout <branch_name>
....

If you want to publish the newly linked submodule version run:

....
$ git add submodule/
$ git commit
$ git push
....

[[development]]
=== Development

The repository contains three apps (Cyface, R4R, Digural), which share the modules of the submodules. Java 21, minSdk 26, compileSdk and targetSdk 35, Gradle with Groovy DSL. All versions are `ext` properties in the root `build.gradle`.

....
./gradlew :ui:cyface:assembleDebug        # build one app (also :ui:r4r, :ui:digural)
./gradlew :ui:cyface:testDebugUnitTest    # unit tests of one app
./gradlew :persistence:testDebugUnitTest  # unit tests of a backend module (also :datacapturing, :synchronization)
./gradlew :ui:cyface:connectedDebugAndroidTest   # instrumented tests (need an emulator or a device)
./gradlew :ui:cyface:lintDebug            # Android lint
....

Modules:

....
ui/cyface, ui/r4r, ui/digural
    └── utils (shared UI: auth, navigation, settings, trips, statistics)
         ├── backend/datacapturing (foreground service for the sensor capture)
         │    └── backend/persistence (Room database: measurements, events, sensor data)
         ├── backend/synchronization (upload to the server, WiFi detection)
         ├── energy_settings (background location prompts)
         └── camera_service (visual capture, used only by Digural)
....

* `:utils` -- shared by all three apps: OAuth 2.0 (AppAuth), navigation, Proto DataStore settings, trips, incentives, map utilities.
* `:ui:cyface` -- the main app with Google Maps, the capturing UI and the settings.
* `:ui:r4r` -- the R4R app with speed display and trip grouping.
* `:ui:digural` -- the Digural app with WebDAV upload (sardine), a Retrofit HTTP client and the camera service. It has its own Proto DataStore settings and its own collector API.
* `backend/`, `energy_settings/` and `camera_service/` are Git submodules. Their versions are also in the root `build.gradle` (`cyfaceAndroidBackendVersion`, `cyfaceEnergySettingsVersion`, `cyfaceCameraServiceVersion`). Update the submodule commit and the version together.

Patterns: MVVM with ViewModel and LiveData, Navigation Component with Safe Args, ViewBinding, Proto DataStore instead of SharedPreferences, `BroadcastReceiver` for the communication between components. Packages: `de.cyface.app`, `de.cyface.app.r4r`, `de.cyface.app.digural`, `de.cyface.app.utils`.

[[github-workflows]]
=== GitHub Workflows

* `gradle_build.yml` builds the three apps and runs their unit tests for each push and pull request to `main` and `release-*`.
* `gradle_connected-tests.yml` runs the instrumented tests of the Cyface app on an API 28 emulator (`google_apis`).
* `gradle_publish.yml` runs on version tags: it builds and signs the three App Bundles, uploads them as artifacts and creates the GitHub release.
* `codeql.yml` runs the CodeQL analysis on pushes and pull requests. It has no weekly run, because GitHub disables a scheduled workflow in a public repository after 60 days without activity.

Pull requests from forks are skipped, because the workflows need the secrets of this repository. The workflows check out the private submodule `camera_service` with the deploy key in `SSH_DEPLOY_KEY_CAMERA_SERVICE`. They write the other secrets into `gradle.properties` and `sentry.properties` through `env:`, never through the script text.

Rules of the workflows (hardening of CY-6748): do not use `${{ github.ref_name }}` or other event values directly in a `run:` script, pass them through `env:`; pass secrets through `env:` of the step that needs them; pin third-party actions to a commit SHA; use `runs-on: ubuntu-26.04`, not `ubuntu-latest`.

[[release-a-new-version]]
=== Release a new version

* The CI sets `versionName` from the tag and `versionCode` from the run number plus 320 in the root `build.gradle`. Do not change them manually.
* Create an annotated tag with a semantic version on `main` and push it. The body of the tag message becomes the release notes.
* The CI builds and signs the App Bundles. Download the artifacts `Signed Cyface Bundle`, `Signed R4R Bundle` and `Signed Digural Bundle` of that run and upload them to the Play Store.
* A tag with a suffix (for example `3.15.1-beta1`) becomes a pre-release.

== Known Issues

The AVD Cache leads to `Install_failed_Update_Incompatible` after a few builds.
- we opened an issue here: https://github.com/ReactiveCircus/android-emulator-runner/issues/319
- we could try to make the AVD cache only be used on main branch like
- see https://github.com/ankidroid/Anki-Android/pull/11032/files?diff=split&w=0
- but for now, we just disabled the AVD cache for the CI to be usable

The CI tests are flaky due to emulator-instability on the CI:
- examples for this, see e.g. https://github.com/leancodepl/patrol/issues/765
- or https://github.com/ReactiveCircus/android-emulator-runner/issues/192
- we could add auto-repeat to the CI workflow, but this is only a workaround
- see https://github.com/ankidroid/Anki-Android/pull/11032/files?diff=split&w=0
